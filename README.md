# ML-Guided ALNS for the Dynamic Dial-a-Ride Problem

This repository contains the code for the MSc thesis *ML-Guided ALNS for the Dynamic Dial-a-Ride Problem* at TU Delft.

> **The complete code is on the [`final-things`](https://github.com/Dido02/thesis-darp/tree/final-things) branch.** Use that branch to build and run the solver. The `main` branch does not contain the build file.

## About

The dynamic Dial-a-Ride Problem (DARP) asks how to route a fleet of vehicles to serve passenger requests that arrive in real time, subject to time windows, vehicle capacity, ride-time limits, and route duration constraints.

This project solves the problem with Adaptive Large Neighborhood Search (ALNS) in a rolling-horizon framework. Arriving requests are inserted greedily, and ALNS reoptimizes the part of the solution that has not yet been executed at fixed epochs. One classifier per destroy-repair pair predicts how reliably that pair improves the solution at the current search state. The resulting selector is compared with random and roulette-wheel operator selection on the Manhattan instances of Fiedler and Mrkos.

## Repository structure

| Folder | Contents |
|---|---|
| `cpp/` | C++ ALNS solver, rolling-horizon simulation, O(1) feasibility test, and tests |
| `ml_train/` | Feature extraction, labelling, classifier training, and ONNX export |
| `benchmarks/` | Benchmark launchers, result parsing, and reports |
| `analysis/` | Data exploration and result analysis |
| `scripts/` | Instance conversion and helper scripts |
| `delftblue/` | Job scripts used to generate training logs on the DelftBlue cluster |
| `src/` | Earlier Python ALNS baseline |

Folders ending in a date contain the scripts of individual experiments. Experiment results, trained models, training logs, and the Manhattan instances are not included.

## Build

The build requires CMake and a C++ compiler. CMake downloads ONNX Runtime and nlohmann/json automatically.

```bash
git clone --branch final-things https://github.com/Dido02/thesis-darp.git
cd thesis-darp/cpp
mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j8
```

To build without ML selection, add `-DENABLE_ML_SELECTION=OFF` to the `cmake` command.

## Run

A static run on a Cordeau instance, from `cpp/build/`:

```bash
./darp_solver --instance ../../data/cordeau/pr01.txt --iterations 5000 --seed 42 --selection roulette
```

A dynamic run needs a converted Manhattan instance (see below):

```bash
./darp_solver --instance ../../data/fiedler_converted/manhattan_30_s_delay03_min.txt \
  --seed 42 --selection roulette --penalty 10000 \
  --dynamic --epoch-length 30 --epoch-budget-ms 1000 --dynamic-stats
```

The options for `--selection` are `random`, `roulette`, and `ml`. ML selection needs exported models:

```bash
--selection ml --ml-model-dir ../../ml_train/models/onnx/ --ml-softmax-temp 0.10
```

## Data

The Manhattan instances come from the ridesharing DARP dataset of Fiedler and Mrkos (2023). After downloading the dataset to `data/fiedler/`, convert an instance from the repository root:

```bash
python scripts/convert_fiedler.py \
  --instance data/fiedler/Instances/Manhattan/instances/start_18-00/duration_01_min/max_delay_10_min \
  --dm data/fiedler/Instances/Manhattan/dm.h5 \
  --output data/fiedler_converted/manhattan_01_min_delay10_min.txt
```

## Training

Python 3.11 or newer is required. Training uses logs generated by the solver in instrumented mode.

```bash
pip install -e "./ml_train[onnx]" matplotlib scipy h5py pyyaml
cd ml_train
python -m darpml extract-features --logs ../trail_logs/ --data ../data/ --out cache/features.parquet --mode dynamic
python -m darpml compute-labels --logs ../trail_logs/ --out cache/labels.parquet --mode dynamic
python -m darpml train --features cache/features.parquet --labels cache/labels.parquet --out models/ --mode dynamic
python export_onnx.py --models-dir models --out-dir models/onnx
```
